Featured case / P2M · Parts2Machines

A tool built for one region, now on a path to global.

I created P2M to answer a question no single system could: which parts dealers should stock for the machines actually working around them. It started in Latin America, was adapted in Australia, and I presented it to the global team as a candidate for one worldwide model.

The problem

Machine population, parts catalogues and dealer inventory lived in separate systems. Teams had long lists, but no view of which parts fit the machines in each territory, or which ones were missing.

The product

P2M uses the parts catalogue as the bridge between machines and inventory. Every answer comes straight from the data platform: no manual files, no spreadsheets in the middle.

My role

Creator and lead: data model, design decisions, live demo and roadmap. Asked by the global data & analytics team to present P2M, I led the discussion on making it a global tool.

How it works

  1. Machine populationEvery machine delivered in the last 20 years, mapped to its current dealer.
  2. Parts catalogueThe bridge: which parts fit each machine model.
  3. Dealer inventoryStock on hand, sales and demand.
  4. Action listCovered vs. missing parts, valued in US dollars.

Design decisions

  • Dealer-group level, not branch level: where assortment decisions actually happen.
  • A 20-year machine window: old accounts remapped to today's dealer network.
  • One price source: official pricing per country, in US dollars.
  • Built to be adopted: standardized English naming, so any region can open it and understand it.

Leading the global scale-up

The limit was volume. I designed the path past it.

One country's machine base alone outweighed the rest of its region, and every regional copy meant one more model to maintain. I presented those limits openly, proposed a roadmap and built a proof of concept to show the model could scale. With AI-assisted development, I standardized the full model in days, not weeks.

Query design · Databricks SQL

From a 300-second timeout to seconds

Users needed to filter machine data by long lists of part numbers, and parsing every list on every row timed out. I parsed the inputs once and switched to semi-joins, so the same search now returns in seconds.

Result: long-list searches became usable as self-service.
